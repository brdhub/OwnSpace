# OwnSpace v4.0.0

发布日期：2026-10-24

## 更新摘要

本版将个人工作台与简历优化流程整合为更完整的求职准备体验，并引入可恢复、带工具调用的简历 Agent 和 GitHub 项目经历解析。

### 个人总览与界面

- 首页改为个人总览，集中展示投递数量、简历文件、记录天数、今日日记、学习、长期规划和日历，保留招聘类型投递统计。
- 增加卡片入场与悬停动效，适配系统减少动态效果设置；标题保持常规字体。
- 新增深浅主题切换，在本机浏览器保存选择。
- 简历优化工作台按准备、优化、审核分步呈现，增大正文与控件字号，使用固定区域和内部滚动，避免内容增长不断撑大页面。

### 投递记录

- 新增记录默认选择秋招，不批量改变历史记录的招聘类型。
- 后续面试支持选择第 2–10 面或保留未指定轮次；轮次变化写入状态轨迹，详情与图片导出同步显示。
- 投递卡片支持快速编辑城市与岗位类型，写入前执行服务端校验。

### 简历 Agent 优化

- 保留最多两次模型请求的快速优化，新增最多八次请求的 Agent 模式。
- 模型通过工具制定计划、按需读取本次已选素材、追问事实、提交建议或结束；程序执行工具白名单、参数与引用校验，反馈错误供模型在剩余额度内修正。
- 使用 LangGraph JS 条件路由、SQLite Checkpointer 和人工中断恢复；展示计划、执行记录和引用依据，建议经人工审核后采用。
- 兼容旧版快速优化存档，按流程版本选择对应图；恢复不重置累计调用次数。
- 参考 Deep Agents JS 的规划与上下文管理思路，没有安装其 SDK、引入子 Agent 或向量数据库。

### GitHub 项目经历解析

- 新入口“简历 → GitHub 项目”：用户填写单个公开仓库、目标岗位与可选 JD，确认后开始分析。
- 固定 commit SHA，获取允许的目录，由模型按需选择关键文件，再按 blob SHA 读取带行号的正文；不执行仓库代码。
- 读取实现代码后暂停确认个人贡献，允许明确跳过；每条项目描述附文件路径、行号和连续原文，经 Zod 与引用校验后进入人工审核。
- 草稿可编辑，确认后幂等写入正式项目条目，再用于 JD 匹配和简历制作。
- 每次任务最多 10 次模型请求、20 次 GitHub 请求、10 个文件；单文件最多 24 KB、代码合计最多 80,000 字符。预算和执行锁持久化，失败或重启后可手动继续。

## 升级说明

在线或离线升级器会先备份个人数据与旧程序，再迁移数据库并构建。源码安装请先备份 `data` 与 `.env.local`，关闭 OwnSpace 服务后执行：

```bash
npm ci
npm run db:migrate
npm run build
npm start
```

本版新增迁移：

- `0026_application_interview_round.sql`：为投递和状态轨迹增加面试轮次，并更新状态变更触发器。
- `0027_github_resume_runs.sql`：新增 GitHub 分析任务、预算、执行锁与正式条目关联。

迁移保留已有业务数据。业务数据库与 `data/langgraph-checkpoints.db` 都需要保留；不要手动删除数据库或用新文件覆盖旧数据。

沿用本机 DeepSeek 配置，模型需支持 Tool Calling。没有新增框架依赖或必填环境变量。GitHub 使用匿名只读 API，不需要 GitHub Token。

## 调用与结果边界

- AI 分析由用户明确发起；一次开始或继续操作可以执行预算内的多轮请求，页面刷新不会自动调用模型，无后台任务队列。
- GitHub 解析仅支持受限大小的公开仓库，不支持私有仓库或执行代码；匿名 API 可能限流。网络故障可能仍显示 `fetch failed`，此版本尚未增加底层网络错误分类与自动重试。
- 引用校验证明原文出处对应，不保证模型结论、个人贡献或线上效果真实；最终描述须人工核对。
- 自动化验证使用模拟模型与网络，不代表真实模型生成质量评估。
