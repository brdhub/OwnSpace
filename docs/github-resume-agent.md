# GitHub 项目解析

入口：`/resumes/github`。基于现有 LangGraph JS、DeepSeek Tool Calling、Zod 与 SQLite Checkpointer，没有新增框架依赖，也没有接入 Deep Agents SDK。

## 流程

1. 用户确认单个公开仓库、目标岗位与 JD 的发送范围。
2. 固定默认分支当前 commit，读取允许的文件目录；不跟随仓库跳转、不运行代码。
3. Agent 通过 `write_plan`、`read_repository_files` 规划并按需读取文件。目录仅接收小型文本文件，排除依赖、构建产物、环境配置及疑似凭据。
4. 读取实现代码后，`request_user_facts` 触发 LangGraph interrupt。用户可补充个人贡献或明确留空跳过；仅浏览页面不会自动继续。
5. `propose_resume_entry` 提交草稿。Zod 检查结构，每条描述至少附一段真实文件的连续原文行，整份草稿至少引用一个实现文件。失败反馈模型修正，所有模型请求共享累计预算。
6. 用户核对并编辑草稿，确认后通过事务写入正式 `resume_entries`。入库操作按运行 ID 幂等，不覆盖已有条目；任务保留生成时的代码证据供追溯。

## 持久化与恢复

- `github_resume_runs`：不可变任务输入、页面状态快照、累计请求次数、执行锁、错误和入库条目关联。
- `thread_id = github:<run UUID>`：从 SQLite Checkpointer 恢复同一次执行，缓存已读文件。
- 模型和 GitHub 请求都先持久化占用额度，再发网络请求。失败或进程退出仍计数，防止恢复造成无限请求。
- 原子执行锁防止重复继续；每次网络请求及状态发布续期，单次模型超时上限 120 秒、GitHub 超时 20 秒，执行锁 180 秒。过期运行可手动接管，旧执行者无法更新业务状态。
- 当前是请求内执行，没有后台队列和自动恢复。任务参数变化需要新建任务。

## 边界

公开代码证明的是项目实现，而非用户的贡献、线上指标或运行效果。原文引用校验不等于语义事实校验。个人职责保留用户补充并由用户编辑，正式入库需人工确认；编辑后描述的事实准确性由用户重新核对。

匿名 GitHub API 有限流；私有仓库、超过 1500 个允许文件、目录被 GitHub 截断、超大文件及二进制文件暂不支持。未读取文件与被排除文件不会纳入模型分析，页面展示已读文件和排除数量。疑似密钥检查是额外防护，不是完整的秘密扫描器。

## 验证

`npx tsx --test test/resumes/github.test.ts` 使用模拟网络与模型、临时 SQLite 验证 URL/文件边界、固定提交与 blob、错误引用、预算与并发占用、磁盘恢复、人工补充及跳过、重复入库。不调用真实模型。
