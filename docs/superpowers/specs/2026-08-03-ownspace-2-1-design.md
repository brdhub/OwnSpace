# OwnSpace 2.1 设计

## 目标

2.1 聚焦简历工作区的紧凑展示与 JD 选材可靠性。全局界面保留安静、低密度的个人工作台风格，不改变其他业务模块的数据结构。

## 界面

- 左上角品牌字号提高一级；全局右下角显示 `v2.1`，原生悬浮提示展示 `2026-08-03` 更新日期。
- 简历调整为左侧导航第三项。
- 页面标题只显示标题，移除所有入口页的副标题。
- 简历仓库首行左侧为 PDF 原件、右侧为 AI 候选审核；结构化条目在下一行横跨整行。
- 结构化条目列表只显示标题和必要的编辑入口，不显示类型、完整度、正文预览或标签。

## JD 匹配

根因是当前 AI 协议允许空结果/部分结果，而默认选择逻辑只选择高匹配。2.1 要求 AI 对每个正式条目给出且只给出一次 `high / medium / low` 评级，服务端验证返回 ID 与输入集合完全一致，并对不合规输出重试一次。

默认选材规则为：优先全部高匹配；没有高匹配时选择全部中匹配；仍没有时选择排序后的第一条低匹配。用户始终可以手动增删。

## 条目描述优化

用户保存选材快照后，可明确点击按钮发起第二次 DeepSeek 请求。AI 只优化所选条目的现有字段值，必须保留原字段键和全部事实，不得虚构数字、技术、职责、规模或成果。

每条建议作为岗位任务内的快照持久化到既有 `resume_optimization_suggestions` 表，原内容和建议内容以 JSON 文本保存。界面并排展示原内容、优化内容和理由，用户可接受或忽略；接受仅改变该任务内建议状态，不直接覆盖正式条目仓库。

## 错误处理

- 未保存选材时禁用优化入口并给出明确提示。
- AI 推荐或优化响应未覆盖完整输入、字段键变化、内容为空或引用未知 ID 时，重试一次；仍不合规则保留任务和用户输入并显示可重试错误。
- 所有 Server Action 输入继续通过 Zod 校验。

## 验证

为默认选材回退、推荐完整覆盖、优化建议字段保真和无效响应重试添加自动化测试；最终运行测试、类型检查、Lint 和生产构建。
