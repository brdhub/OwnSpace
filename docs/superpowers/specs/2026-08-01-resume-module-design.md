# 第二阶段：简历模块与 AI 优化设计

## 目标与范围

第二阶段在现有本地优先的求职助手中新增唯一的侧边栏入口「简历」。进入模块后默认展示简历仓库，并在模块内进入「简历优化」。

本阶段交付：

- PDF 简历原件仓库。
- 可复用、可编辑的结构化简历条目仓库。
- 基于 JD 文本或 JD 图片的 AI 简历优化工作台。
- 经用户确认后保存的岗位文本版简历。
- 仅针对指定飞书多维表格的可选岗位同步基础设施。

不在本阶段交付：PDF/Word 导出、通用网页抓取、后台队列、云同步、多用户或自动修改原始简历。

## 用户体验与导航

侧边栏只新增「简历」入口，避免把仓库和优化拆成两个平级功能。

简历页包含两个内部入口：

1. **简历仓库（默认）**：上半部分为 PDF 原件列表；下半部分为紧凑的条目仓库，可按类型筛选、搜索、新增和编辑。
2. **简历优化**：创建并管理 JD 优化任务；历史任务在同一入口内可回看。

条目仓库的第一版固定支持五类素材：个人信息、教育经历、实习/工作、项目/科研、技能/证书。获奖和校园经历暂不做独立一级类型，后续按真实需求扩展。

## 领域模型

### 1. PDF 原件

每次上传保存一份不可变的 PDF 文件及其元数据：显示名称、存储路径、文件大小、上传时间、解析状态、提取文本和解析错误。原始文件永不被 AI 覆盖或修改。

### 2. 简历条目

条目是可复用的真实素材。所有条目包含类型、标题、结构化内容、标签、完整度和更新时间。具体类型的字段由各自 Zod schema 校验，例如教育条目的学校、专业、时间与研究方向；项目条目的职责、工具和已确认成果。

条目内容只记录用户提供或明确确认的事实。对缺失数字、职责范围或结果，记录为待补信息，而不是由 AI 补写。

### 3. JD 优化任务

优化任务保存：JD 来源（粘贴文本或图片）、已确认的 JD 文本、目标岗位信息、用户选择的 PDF 和条目快照、AI 输出、状态和创建时间。

任务完成后，用户逐条接受或忽略建议。已接受建议生成一份岗位文本版；该版本引用创建时的素材快照，因此之后修改条目不会篡改既有版本。

### 4. 飞书岗位数据

飞书数据独立于简历素材。同步时保存同步记录、来源 URL、同步时间、原始快照摘要、规范化岗位字段及错误信息。第一阶段仅允许这一来源：

## 数据流

```text
上传 PDF → 本地文件存储 → 提取文本（可失败） → 用户编辑/维护条目

粘贴 JD 或上传 JD 图片 → OCR → 用户确认/编辑 JD 文本
→ 选择 PDF 与条目 → AI 优化 → 逐条确认建议 → 岗位文本版快照

指定飞书表格 → 用户手动触发同步 → 规范化岗位记录 → 后续可选作 JD 来源
```

JD 图片 OCR 的结果必须先展示给用户编辑或确认，确认前不发送给 AI。AI 请求只发送该次任务已确认的 JD 文本、用户主动选择的条目和需要分析的 PDF 提取文本；不自动发送整个简历仓库。

## AI 集成

AI 层实现为模块内的兼容 OpenAI 协议适配器，第一版默认配置为 DeepSeek V4。密钥、基础 URL、模型名等只存在本机 `.env.local`；SQLite 中不得写入任何密钥。

AI 输出采用可校验的结构：

- JD 关键要求与匹配度概览。
- 已匹配的素材及其依据。
- 缺失事实的少量追问。
- 可单独确认的逐条改写建议。
- 仅由确认建议组成的文本版岗位简历。

优化规则采用三层方法：信息卫生、业务价值翻译、经历挖掘。所有输出遵守保真原则：不得虚构经历、职责、技能、数据或业务规模；信息不足时必须提出问题，而非猜测。

## 模块边界

新增业务逻辑放在 `src/features/resumes/` 下，包含页面组件、Server Actions、查询、Zod schema、文件处理、OCR 协调、AI 适配器和测试。`src/app/resumes/` 仅负责路由和页面组合。共享 UI 仅在确有通用性时放入 `src/components/ui/`。

数据库改动通过 Drizzle schema 和 migration 完成。文件本体作为本地资产保存，SQLite 仍是全部业务元数据的唯一数据源。所有写入操作通过 Server Actions 和 Zod 校验；不得新建泛化的 `services/` 目录。

## 工程约束的定向调整

实施前需要更新根目录 `AGENTS.md` 所指向的工程约束文件，形成严格的例外白名单：

- 允许用户主动上传的本地 PDF、JD 图片及其本地处理。
- 允许对用户确认内容调用配置好的 DeepSeek 兼容 API。
- 允许仅对上述单一飞书多维表格执行用户手动触发的同步。

继续禁止未授权的第三方抓取、云同步、自动外发整个仓库、后台任务队列和任何绕过站点权限的行为。

## 错误处理与空状态

- 空仓库提供简短的上传 PDF 与新增条目引导。
- PDF 无法解析时仍保留原件，并提示用户手动补充条目。
- JD 图片 OCR 失败时保留图片并提供粘贴文本入口。
- AI 配置缺失、网络错误或返回格式异常时，保留任务和用户输入，给出可重试提示。
- 飞书同步失败时保存失败原因与时间，既有岗位数据不被删除。

## 验收与测试

- PDF/图片格式、大小和必填字段校验。
- 五类条目的新增、编辑、删除、筛选和搜索。
- JD 文本确认流程及 OCR 失败回退。
- AI 请求只包含已确认、已选择内容；响应按 Zod 结构校验。
- 接受建议后生成不可变的岗位版本快照。
- 飞书同步的成功、无权限、结构变化和网络失败场景。
- TypeScript、Lint、现有功能回归和数据库 migration 验证。

## 实施顺序

1. 更新工程约束的窄范围例外，并添加数据库 migration。
2. 实现简历入口、PDF 原件和五类条目仓库。
3. 实现 JD 文本/图片输入、OCR 确认流程和优化任务。
4. 接入 DeepSeek 兼容 API、建议确认和岗位文本版快照。
5. 实现单一飞书来源的手动同步和岗位记录基础。
