# OwnSpace 简历复制与投递 JD 持久化联动设计

**日期：** 2026-08-23  
**状态：** 已确认，待实施

## 1. 背景与目标

OwnSpace 已具备结构化简历条目、手工 JD 匹配、DeepSeek 条目推荐与描述优化能力，但投递记录尚未保存岗位描述，简历条目详情也偏重阅读而非向招聘网站复制。本轮建立从投递记录到简历选材的持久化链路，并为后续面试模拟保留一个明确入口。

本轮目标：

1. 让结构化简历条目的每个实际字段都能快速、准确地单独复制。
2. 为投递记录增加可选岗位描述，并纳入现有新增、编辑、查询流程。
3. 从投递记录一键进入简历 JD 匹配，复用岗位、JD 和历史匹配任务。
4. 在投递记录与 AI 工具页预留面试模拟入口，但本轮不生成提示词、不调用 AI。

## 2. 本轮不做

- 不提供“复制全部”。
- 不复制简历条目的内部标签。
- 不读取或发送上传的 PDF 简历原文。
- 不生成面试问题、答案或模拟面试提示词。
- 不自动打开、粘贴或发送内容到 ChatGPT、Claude、DeepSeek。
- 不接入 OpenAI API、Web Search 或新的外部 AI API。
- 不建立通用 AI 上下文、对话或面试模拟数据表。

## 3. 核心方案

采用持久化联动，而不是把完整 JD 放入 URL。投递记录保存当前岗位描述；JD 匹配任务保存来源投递 ID，同时继续保存目标岗位和 JD 快照。页面跳转只携带投递 ID，由服务端读取合法数据。

这样可以满足：

- 长 JD 不受 URL 长度限制，也不会暴露在地址栏。
- 投递记录修改 JD 后，既有匹配任务仍保留当时使用的快照。
- 删除投递记录不会删除简历匹配历史。
- 下一次实现面试模拟时，可以稳定读取投递和已选简历条目。

## 4. 数据模型

新增一条 Drizzle migration，不删除、不重建现有表。

### 4.1 `applications`

新增：

```text
job_description TEXT NOT NULL DEFAULT ''
```

产品语义为可选字段；数据库使用空字符串表示未填写，与现有 `notes` 一致。输入经过 Zod 去除首尾空白，最大长度 20,000 字符。

### 4.2 `resume_optimization_tasks`

新增：

```text
application_id INTEGER NULL
  REFERENCES applications(id)
  ON DELETE SET NULL
```

并为 `application_id` 建立普通索引，便于查询某次投递最近的 JD 匹配任务。

`jd_source` 仍表示输入介质（当前文本或图片），从投递导入时仍为 `text`；`application_id` 单独表示业务来源，不混用两个概念。

任务创建时将当时的 `role` 和 `job_description` 分别写入 `target_role`、`jd_text`。后续投递内容修改不回写历史任务。

## 5. 模块边界

### 5.1 投递模块

负责：

- 岗位描述的新增、编辑、校验和展示状态。
- 提供合法、只读的投递 JD 上下文查询。
- 生成到简历 JD 匹配页和 AI 工具页的入口链接。

不负责运行 AI 或选择简历条目。

### 5.2 简历模块

负责：

- 结构化条目字段级复制。
- 从合法投递 ID 导入目标岗位和 JD。
- 将来源投递 ID写入新建的 JD 匹配任务。
- 打开该投递最近一次历史任务，或预填一个尚未提交的新任务。

### 5.3 AI 工具模块

本轮只负责展示“面试模拟”入口与规划中状态。若从投递记录进入，显示已关联的公司和岗位，证明入口上下文传递有效；不展示完整 JD，不发起外部请求。

## 6. 简历字段级复制体验

复制入口放在现有条目详情弹窗中，不改变条目列表的信息密度。

- 条目标题：复制精确标题文本。
- 项目经历：项目分类、技术栈、项目内容分别复制。
- 实习经历：岗位、技术栈、工作职责、工作内容分别复制。
- 教育背景：学历、专业、时间、教育经历分别复制。
- 专业技能：掌握程度、技能说明分别复制。
- 荣誉认证：奖项/等级单独复制。
- 技术栈数组复制为使用中文顿号连接的纯文本。
- 标签继续用于内部识别和筛选，不提供复制入口。
- 空字段不渲染复制按钮。

每个字段标题或内容区域旁放置小型复制按钮。复制成功后原位置短暂显示“已复制”；失败时显示“复制失败，请手动选择”。不使用全局弹窗，不改变剪贴板内容格式，不增加依赖。

复制字段的生成规则抽成简历模块内的纯函数，详情 UI 与测试共用同一结果，避免各条目类型分散维护。

## 7. 投递记录体验

### 7.1 新增与编辑

投递表单在投递网址与备注附近增加“岗位描述（可选）”多行文本框，适合粘贴完整 JD。错误信息沿用现有表单样式。

### 7.2 投递卡片

- 已填写 JD：展示低强调度“已有 JD”标识，并显示“JD 匹配”和“面试模拟”入口。
- 未填写 JD：不显示“已有 JD”；以“补充 JD”入口打开当前投递的编辑表单，不允许空 JD 进入匹配流程。

卡片不直接展开完整 JD，避免投递列表过长。

## 8. JD 匹配持久化联动

入口 URL：

```text
/resumes?tab=jd&applicationId=<positive integer>
```

处理流程：

1. 简历页面服务端解析并校验查询参数。
2. 按 ID 查询投递，只返回 `id`、`company`、`role`、`jobDescription`。
3. ID 无效、记录不存在或 JD 为空时，不加载其他投递数据，并显示明确提示。
4. 有效时自动切换到 JD 匹配标签。
5. 如果该投递已有任务，默认打开更新时间最近的任务。
6. 如果没有历史任务，以投递岗位和 JD 预填新任务表单。
7. 页面跳转不调用 DeepSeek；仍需用户点击“AI 推荐条目”。
8. 创建任务时通过隐藏字段提交 `applicationId`。服务端再次确认投递存在，并写入任务关联和输入快照。

用户可以在匹配页编辑预填的岗位或 JD；编辑值只属于新任务快照，不反向修改投递记录。若要修改投递的正式 JD，仍回到投递记录编辑。

## 9. 面试模拟预留入口

投递卡片入口 URL：

```text
/ai-hub?applicationId=<positive integer>#interview-simulator
```

AI 工具页顶部增加“面试模拟”卡片：

- 无投递上下文时：展示功能简介与“将在后续版本开放”。
- 有合法投递上下文时：展示公司、岗位和“已关联此投递”。
- ID 无效或记录已删除时：展示“未找到对应投递”，不泄露其他记录。
- 不展示完整 JD，不读取简历条目，不生成提示词，不发送数据。

下一次迭代可在该入口下扩展：默认使用该投递最近一次 JD 匹配任务中保存的条目，生成交互式模拟面试提示词，并通过“复制后打开外部 AI”或 API 完成后续流程。

## 10. 校验与错误处理

- `jobDescription`：可空，最大 20,000 字符。
- `applicationId`：必须是正整数，客户端传值不可信，服务端查询是最终边界。
- 创建关联任务时，如果投递在提交前被删除，返回表单错误，不创建无来源任务。
- Clipboard API 失败时保留可选择的原文本，并显示局部错误状态。
- 删除投递时依赖外键 `SET NULL` 保留任务；任务的岗位和 JD 快照不变。
- 所有新增写操作继续通过 Server Actions 和 Zod。
- 本轮不新增任何外部调用，因此无需修改外部访问白名单。

## 11. 测试与验证

### 11.1 自动化测试

- 投递 schema：空 JD、合法 JD、20,000 字符边界、超长拒绝。
- 投递持久化：创建和更新时保存岗位描述。
- 数据库迁移：原有记录得到空字符串；删除投递后任务保留且关联置空。
- JD 导入：有效投递预填、最近历史任务优先、空 JD、无效 ID、已删除记录。
- JD 任务 action：合法关联写入；伪造或不存在的 `applicationId` 被拒绝。
- 简历复制字段纯函数：五类条目的字段清单、空字段过滤、技术栈顿号连接、标签不进入复制项。
- AI 工具入口：合法上下文、无上下文和无效上下文三种只读状态；不得触发 AI 方法。

## 12. 完成标准

1. 用户能在条目详情中逐字段复制，不存在“复制全部”。
2. 投递记录可选保存岗位描述，旧数据无损迁移。
3. 有 JD 的投递可一键进入简历 JD 匹配并复用持久化关联。
4. 跳转不会自动调用 DeepSeek。
5. 投递卡片和 AI 工具页均有面试模拟入口，但不实现模拟功能。
6. 删除投递不删除历史简历匹配任务。
7. 自动化测试、类型检查、Lint、生产构建和差异检查通过。
