# 简历优化工作流：从代码到使用

本次实现的是固定业务路径上的条件分支与有限修正，不是模型自由选择工具的 ReAct Agent。

## 从哪里开始读

1. `src/features/resumes/workflow/resumable-graph.ts`：State、Node、Edge、interrupt。
2. `validation.ts`：程序检查模型输出，保留合格条目，识别失败素材。
3. `checkpoint-store.ts`：官方 SqliteSaver，负责序列化与读取检查点。
4. `recovery-service.ts`：业务运行、调用次数、执行占用、输入版本和幂等保存。
5. `recovery-actions.ts`：页面按钮到工作流的入口。
   `recovery-runner.ts`：读取检查点、区别未回答与明确跳过、恢复执行及完成态重放。
6. `src/features/resumes/deepseek-core.ts` 的 `requestOptimizationOnce`：一次模型请求，不嵌套重试。

旧 `optimization-graph.ts` 保留原有校验工具与兼容测试；页面的优化入口已切换到新的可恢复图。

## 实际执行顺序

```text
prepare → [单条重写时 awaitFacts 暂停] → generate → validate
                                                   ├─ 合格 → finish
                                                   ├─ 失败且未修正 → repair → validate
                                                   └─ 已修正或预算用完 → finish（失败项原文回退）
```

`prepare` 检查输入；`generate` 请求模型；`validate` 只运行程序规则；`repair` 携带错误和失败素材再请求一次；`finish` 输出完整条目列表。元数据和原本为空的字段不得改写。固定字段保护不代表正文绝无夸大，仍需要人工审核。

## Checkpoint 保存在哪里、是什么

- 现有 `data/ownspace.db`：正式素材、建议、草稿、版本、运行记录和调用预算。
- 新增 `data/langgraph-checkpoints.db`：LangGraph 检查点和待处理写入；首次使用工作流时自动建立。表结构由官方适配器管理，不混入 Drizzle 业务迁移。
- SQLite 开启 WAL 时旁边可能出现 `-wal`、`-shm` 文件。备份时关闭应用后一起备份 data，或使用 SQLite 备份 API，不要在运行中只拷贝主文件。
- 状态经过适配器序列化保存为表记录，不是一个检查点一个 JSON 文件，也不是 PDF 文件。

State 包含输入素材快照、JD、工作流版本、补充事实、原始模型结果、有效建议、失败素材 ID、校验问题、调用/修正次数、已知 token 用量。框架另存检查点 ID、执行版本及任务调度信息。业务运行 ID 同时用作 `thread_id`；每次新优化创建一个 ID，恢复时复用原 ID。

State 不保存 API Key、数据库连接或模型内部推理；保存在本机的简历文本仍属于个人数据。已结束或失败的运行可通过“清理执行存档”删除图存档和运行输入快照，保留成品。等待中的流程可通过发起新优化替代。

## 使用方式

1. 在“简历 → JD 匹配”保存岗位、JD 与选材，点击“优化已选描述”。默认最多两次请求，含一次定向修正。
2. 页面显示阶段、请求次数、已记录耗时和 token。供应商没返回用量时显示“未知”。
3. 失败后点击“从已保存进度继续”。应用意外结束后，运行占用超过五分钟会显示中断，允许继续；不会后台自动运行。
4. 在一条有效建议下点击“补充事实后重写此条”，先创建不调用模型的等待存档。
5. 在进度区填本人负责的工作、措施、可核实结果，然后继续。可以留空跳过。补充只用于目标素材，不改正式条目库；此条新建议需要重新审核，其他条目的审阅状态保留。
6. 已接受建议进入新生成的草稿；既有草稿与版本不会因重写自动改变。

## 恢复时为何不会乱写

恢复先检查 `inputRevision`、工作流版本、模型配置、运行状态，再取得新的 `executionId`。旧执行不能使用新占用写回；输入变化或新的优化会使未完成旧运行失效。模型请求前在业务数据库中预占次数，即使请求后、检查点前崩溃，恢复也不会重置两次总预算。结果写入与完成标记使用事务，重复完成不会重复插入建议。

检查点只能复用已经落盘的结果：如果模型已经收费但结果没来得及落盘，仍可能重做或损失结果。这里没有承诺调用恰好一次。

## 解析错误的边界

PDF 本地文字读取失败、扫描版没有文字、模型结构整理失败分别提示。候选提取对可修正的 JSON/结构/原文引用错误最多指导修正一次；网络和 HTTP 错误立即返回。来源片段会与提取文字进行空白归一化匹配，候选必须由用户确认入库。成功前不替换旧候选。

本轮没有新增 OCR，也没有把 PDF 提取纳入检查点图。原文理解是否正确仍需要候选与原文对照。
